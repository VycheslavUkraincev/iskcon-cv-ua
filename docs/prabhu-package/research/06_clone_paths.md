# Исследование 6. Технологии «взять готовый сайт и сделать второй макет»

Дата: 2026-10-22. Объект: iskcon.cv.ua, репозиторий `VycheslavUkraincev/iskcon-cv-ua`, актуальная ветка `gh-pages`.

## 0. Исходные условия именно этого проекта (проверено по дереву gh-pages)

- Статичный HTML без сборочного шага: GitHub Pages отдаёт файлы как есть. Всего в ветке 164 файла.
- Страниц немного: `index.html`, `courses.html`, `donation.html`, `food.html` плюс папки-дубли `courses/index.html`, `donation/index.html`, `food/index.html`.
- Трёхъязычность UK / EN / RO сделана кодом, а не отдельными страницами: `assets/i18n.js` + `assets/i18n-dict.js`. Плюс, по отзывам общины, у логотипа «Їжа життя» есть 3 языковые версии картинкой.
- Формы: внешние Google-формы Анади Кришны (регистрация на курсы, волонтёры Food for Life), аналитика и embed-видео живут ссылками/вставками, а не бэкендом.
- Вывод из этих трёх фактов: проекту **не нужна миграция на другую платформу или фреймворк**. Нужна та же папка файлов, с новым дизайном. Это сразу определяет ranking путей ниже.

## Путь A. Зеркало репозитория → ветка `mockup-v2` → Claude Code редизайнит на месте

### A1. Основной вариант: `git clone` (не wget)

```bash
git clone -b gh-pages https://github.com/VycheslavUkraincev/iskcon-cv-ua.git iskcon-mockup
cd iskcon-mockup
git checkout -b mockup-v2
git tag pre-redesign-snapshot   # точка отката до коммита в gh-pages
```

Почему clone, а не зеркало с живого сайта: в репозитории уже лежат оригиналы всех 164 файлов, включая то, что живой сайт не показывает напрямую (i18n-словарь, исходники фото, `MEDIA.md`, `.agents/skills/frontend-design`). Ничего не теряется и не угадывается.

### A2. Запасной/проверочный вариант внутри A: `wget --mirror`

Классическая команда зеркалирования: `wget --mirror --convert-links --adjust-extension --page-requisites --no-parent https://iskcon.cv.ua/` — `--mirror` включает рекурсию, `--page-requisites` тянет картинки и CSS, `--convert-links` делает копию пригодной для офлайн-просмотра. Источник: https://catonmat.net/cookbooks/wget/mirror-website

Ограничения зеркала, важные именно здесь: копировщики сохраняют то, что прислал сервер, и **не выполняют JavaScript**, поэтому lazy-loaded картинки при скролле часто пропадают, а формы и поиск в копии не работают. Источник: https://dev.to/petr_savenok/how-to-download-a-website-as-a-zip-file-ojo

Для iskcon.cv.ua это критично: переключение языка делается JS (`i18n.js`), значит wget-копия покажет только одну языковую версию и «потеряет» словарь. Поэтому wget годится только как контрольный снимок «как сайт видит посетитель», а не как исходник макета.

### A3. Редизайн Claude Code на месте, с жёсткими guardrails

В `CLAUDE.md` ветки `mockup-v2` фиксируется список «не трогать молча»:

- список URL и имён файлов (все 7 HTML), якорные `id` секций;
- подписи навигации на трёх языках и все ключи `i18n-dict.js` (новые строки дизайна добавляются сразу в UK/EN/RO);
- ссылки на Google-формы, embed видео «Шпальта Медіа», ссылки Instagram/YouTube/Telegram/Google Maps;
- код аналитики, meta/OG-теги, `lang`, alt-тексты;
- 3 языковые версии логотипа «Їжа життя» (баг из отзывов: обрезанный и непереведённый логотип не должен вернуться).

Дальше редизайн идёт срезами: hero → расписание/программы → курсы → Food for Life → пожертвования → FAQ → контакты, с Playwright-скриншотами 1440px и 375px после каждого среза и visual diff против базовой ветки.

### Оценка A

| Критерий | Оценка |
|---|---|
| Скорость первого макета | Клон: минуты. Первый видимый срез (hero + главная): часы работы агента. Весь сайт: это часы–дни итераций, а не минуты, зато без переделки |
| Качество | Максимальное из трёх путей: работа идёт с реальным кодом, текстами и фото, а не с реконструкцией по скриншоту |
| Контроль над кодом | Полный: `git diff` по каждому коммиту, откат одной командой, история сохраняется |
| Вернуть в GitHub Pages | Нативно, это тот же репозиторий. Нюанс превью: см. раздел «Превью» ниже |
| Цена | $0 за инструменты сверх подписки Claude (Opus), которой проект уже располагает |
| Риски | Только дисциплинарные: агент может «молча» поменять URL/ключи i18n, поэтому нужен checklist-diff (раздел «Риски») |

## Путь B. URL-клонеры (чужие платформы)

Общее для всех: вставляешь URL, AI пересобирает страницу по тому, что видит посетитель. Общий потолок жанра сформулирован у Hostinger: результат это «close starting point, not a pixel-perfect duplicate», часть layout и анимаций не переносится. Источник: https://www.hostinger.com/ai-builder/website-cloner

### B1. Hostinger AI Website Cloner

- Что даёт: читает **одну** публичную страницу по URL и строит редактируемую версию внутри AI Builder, правки промптами или визуально, заявлено и полное редактирование кода. Источники: https://www.hostinger.com/blog/website-from-url-launch/ , https://www.hostinger.com/ai-builder/website-cloner
- Ограничения: одна страница за проход; то, что строится после загрузки/взаимодействия и лежит за логином, не захватывается; серверную функциональность (формы, базы, интеграции) надо переподключать вручную. Источник: https://www.hostinger.com/tutorials/?p=69634
- Экспорт / lock-in: данные источников расходятся. По одному обзору, сайты классического drag-and-drop билдера Hostinger экспортировать нельзя, а у agentic-проектов есть просмотр и экспорт кода; по другому, редактированный код обратно в AI Builder не импортируется. Источники: https://max-productive.ai/ai-tools/hostinger-ai-website-builder/ , https://hostscore.net/review/hostinger-ai-builder/
- Цена/лимиты: старт бесплатно без карты, с AI-кредитами на первую генерацию; публикация — платный план, хостинг и домен включены. В обзорах фигурируют планы от $2.99/мес (48 мес предоплаты, 5 AI-кредитов) до $6.99/мес Explorer (30 кредитов): цены в источниках расходятся и меняются, проверять в checkout. Источники: https://www.hostinger.com/ai-builder/website-cloner , https://gizmodo.com/best-website-builder/ai , https://kingy.ai/news/craft-stunning-websites-in-minutes-with-hostingers-ai-website-builder/
- Вердикт для iskcon: годится показать Анади/общине «как мог бы выглядеть сайт на другом конструкторе», но уводит проект с бесплатного GitHub Pages на платный хостинг. Как источник продакшн-кода не использовать без предварительной проверки экспорта.

### B2. AIDesigner Website Cloner

- Что даёт: клон пересобирается в **чистый семантический HTML + Tailwind CSS, а не в замороженное зеркало**, код можно экспортировать в любой момент («no lock-in»), править визуально или AI-чатом и передать coding-агенту, в т.ч. через MCP в Claude Code. Источник: https://www.aidesigner.ai/website-cloner
- Ограничения: **каждый клон захватывает одну страницу с одного URL**, многостраничный сайт клонируется постранично, потом страницы надо связывать и выравнивать навигацию/брендинг вручную. Сайты за логином и с тяжёлым JS-рендером поддерживаются ограниченно. Источник: https://www.aidesigner.ai/website-cloner
- Цена/лимиты: в FAQ клонера — 1 кредит за клон, новым пользователям дают бесплатные кредиты; в более новых материалах AIDesigner reference-режимы (clone/enhance) стоят 2 кредита. Бесплатный тариф: 5 lifetime-кредитов без карты, Pro от $25/мес за 100 кредитов. Расхождение 1 vs 2 кредита фиксируем как есть, проверять в кабинете. Источники: https://www.aidesigner.ai/website-cloner , https://www.aidesigner.ai/blog/what-is-vibe-coding , https://www.aidesigner.ai/blog/best-ai-landing-page-builders
- Вердикт для iskcon: **лучший из клонеров именно как запасной путь**. 4 страницы × 2 кредита укладываются даже в бесплатные/минимальные лимиты, а экспорт HTML+Tailwind реально вернуть в репозиторий (хотя Tailwind добавит сайту сборочный/CDN-шаг, которого сейчас нет, это надо осознанно принять или попросить экспорт в plain CSS).

### B3. Repaint

- Что даёт: самый тщательный импорт в жанре: подтягивает страницы, тексты, картинки, шрифты и цвета бренда и пересобирает **несколько страниц под структуру оригинала, где большинство инструментов останавливаются на главной**. Правки чатом, хостинг включён. Источник: https://repaint.com/blog/best-ai-website-redesign-tools-2026
- Процесс: вставить URL → Repaint сам задаёт вопросы и пишет план на ревью → генерация → временный Repaint-адрес для превью при живом оригинале → подключение своего домена через DNS. Источник: https://repaint.com/blog/how-to-modernize-an-outdated-website-with-ai
- SEO-заявление вендора: умеет сохранять адреса страниц и контент, а при переезде страницы ставить автоматический редирект; перед запуском можно попросить проверить отсутствующие страницы и битые ссылки. Источник: https://repaint.com/website-redesign
- Цена/лимиты: 14 дней бесплатно (включая публикацию и свой домен), платные планы от $25/мес, внутри недельный лимит AI-использования; для сайтов из сотен страниц импортируется сначала только часть контента. Источник: https://repaint.com/website-redesign
- Главный минус для iskcon: **экспорт кода обратно в GitHub в найденных материалах не заявлен** — модель продукта «Repaint hosts the site». То есть это смена хостинга и платформы, а не второй макет в своём репозитории.
- Вердикт: идеален как быстрый визуальный бенчмарк «весь сайт целиком за один день для обсуждения с общиной», непригоден как основной путь, если цель остаться на GitHub Pages.

### B4. Capacity (URL → React + Tailwind)

- Что даёт: URL одной страницы → скриншот 1280px, чтение текста, картинок и вычисленных стилей → проект на **React + Tailwind примерно за 10 минут** (их пример: главная cal.com склонирована за 10.9 мин). Источник: https://capacity.so/clone-website-ai
- Ограничения, честно перечисленные самим вендором: не pixel-perfect (заголовки получились светлее), шрифт не с Google Fonts заменяется ближайшим бесплатным, **очень длинная страница обрезается после 7000px**, картинки продолжают грузиться с адресов оригинала, их надо заменять своими до публикации. Источник: https://capacity.so/clone-website-ai
- Цена/лимиты: клонирование требует платного плана и кредитов; тарифы от Starter $25/мес (100 кредитов, скачивание всей кодовой базы включено). На странице клонера в разборе из поиска фигурировало «минимум 5 кредитов на клон». Источник: https://capacity.so/upgrade
- Вердикт для iskcon: **не рекомендуется**. Он меняет стек: вместо статичного HTML появляется React-проект, которому для GitHub Pages нужна сборка через GitHub Actions. Платим сложностью, не получая ничего, чего нет в пути A. Плюс главная страница iskcon длинная, риск обрезки после 7000px вполне реальный.

### B5. UX Pilot (Website Cloner)

- Что даёт: URL, скриншот или референс → редактируемая high-fidelity версия; экспорт **в Figma или production-ready HTML**, «you own the output». Бесплатно можно сгенерировать 7 страниц без карты. Источник: https://uxpilot.ai/news_sitemap.xml/website-cloner
- Вердикт для iskcon: не самостоятельный путь, а **мост между B и C**: бесплатно клонировать/перепридумать экраны, уйти в Figma на обсуждение с общиной, а оттуда в код (см. C2). Цена платных тарифов в найденных источниках не зафиксирована, проверять на сайте.

## Путь C. Screenshot / image-to-code и Figma-путь

### C1. Screenshot-to-Code

- Инструмент-эталон: open-source `abi/screenshot-to-code` (MIT): скриншот, мокап, экспорт из Figma или даже screen recording превращаются в код HTML+Tailwind, HTML+CSS, React+Tailwind, Vue+Tailwind, Bootstrap, Ionic; работает на своих ключах OpenAI/Anthropic/Gemini или в hosted-версии. Источники: https://github.com/abi/screenshot-to-code , https://www.open-source-tools.com/screenshot-to-code
- AIDesigner умеет то же внутри B2: image-to-HTML из скриншота/мокапа. Источник: https://www.aidesigner.ai/website-cloner
- Фундаментальное ограничение метода: картинка теряет точные данные. В разборе capture-инструментов прямо перечислено: скриншот теряет настоящий шрифт (модель угадывает Inter), точные цвета, отступы и радиусы, весь текст ниже сгиба и данные (карточки превращаются в hardcode/placeholder). Источник: https://dev.to/eklavya_pandey_163f26590b/i-built-a-tool-that-reverse-engineers-any-website-into-react-in-one-command-heres-how-the-capture-35bc
- Роль в проекте: **не клонировать свой сайт, а переносить чужие референсы**. Нашёл на Awwwards hero/секцию → скриншот → screenshot-to-code даёт черновой HTML-фрагмент → Claude Code в пути A встраивает его в реальную страницу с реальными текстами и i18n. Быстро (минуты на фрагмент), дёшево, качество фрагмента среднее, но его всё равно переписывать.

### C2. Figma-путь: дизайн в Figma → Figma MCP → Claude Code

- Схема: референс или клон из UX Pilot собирается/правится в Figma (это удобно показать и обсудить с непрограммистами общины) → фрейм отдаётся Claude Code через Figma MCP.
- Ключевое преимущество перед скриншотом: `get_design_context` возвращает **структурные данные, а не плоскую картинку**: дерево слоёв, типографику, цвета из переменных Figma, отступы Auto Layout, варианты компонентов и Code Connect-связки с реальными компонентами проекта. Источник: https://www.925studios.co/blog/2026-03-18-how-to-use-figma-mcp-with-claude-code-the-complete-playbook-2026
- Интеграция двусторонняя и официальная: в феврале 2026 Anthropic и Figma выпустили first-class интеграцию через Figma MCP (design → code и code → design), установка `claude plugin install figma@claude-plugins-official`, Dev Mode MCP требует платного плана Figma. Источник: https://open-design.ai/agents/claude-code-design/
- Цена/условия: нужен платный Figma seat с Dev Mode (в сравнении AIDesigner: Figma Professional Full seat $16/мес при помесячной оплате). Источник: https://www.aidesigner.ai/blog/aidesigner-vs-figma
- Вердикт: оправдан только если макет будут **обсуждать и править руками в Figma** (община, Анади). Если обсуждать готовы сразу живое превью сайта, Figma-этап это лишнее звено между референсом и кодом.

## Общие риски всех путей (и как их закрывать)

1. **SEO.** Нельзя менять адреса страниц и терять индексируемый контент. У проекта уже есть зона риска: одни и те же страницы лежат и как `courses.html`, и как `courses/index.html` — при редизайне не плодить третью версию адресов, сохранить существующие URL 1-в-1 и проверить canonical/редиректы. Repaint заявляет сохранение адресов и авторедиректы, но это его хостинг, не наш. Источник: https://repaint.com/website-redesign
2. **Дубли контента на превью.** Превью макета на публичном втором домене — это полный дубль сайта для поисковика. Закрывать: `noindex`, отдельный поддомен/репо без CNAME основного домена, не подключать iskcon.cv.ua к превью ни на день.
3. **Потеря i18n (самый недооценённый риск).** Все URL-клонеры читают сайт **в одной языковой версии**, в которой его открыли. EN и RO версии при клонировании просто не существуют для инструмента, а словарь `i18n-dict.js` не виден снаружи в принципе. В пути A словарь лежит в репозитории и сохраняется автоматически. В путях B каждую страницу пришлось бы клонировать 3 раза и потом всё равно сшивать языки руками, включая 3 версии логотипа из отзывов.
4. **Формы и аналитика.** Копировщики и клонеры не переносят серверную часть: формы, счётчики, embed надо переподключать вручную, это прямо предупреждается в гайдах по клонированию. Источник: https://www.hostinger.com/tutorials/?p=69634 . В пути A ссылки на Google-формы и код аналитики уже в файлах, риск только в том, что агент их перепишет, поэтому они в «не трогать»-списке.
5. **Горячие ссылки на картинки.** Capacity прямо пишет: в клоне картинки продолжают грузиться с адресов оригинала, до публикации их надо заменить своими. Та же болезнь у большинства клонеров. В пути A все фото уже локальные в `assets/`.
6. **Права на контент.** Все вендоры клонеров требуют: клонировать только сайты, на которые есть права. Для своего сайта проблемы нет, а вот референсы с Awwwards в пути C берём как структуру/идею, не как чужие тексты и фото.

## Превью макета при пути A (важный нюанс GitHub Pages)

У одного репозитория GitHub Pages публикуется **из одного источника** (Settings → Pages → Deploy from a branch), встроенных deploy previews для веток у GitHub Pages нет, для превью нужна отдельная staging-настройка или Actions. Источники: https://guides.codepath.org/webdev/Deployment-with-GitHub-Pages , https://knowledgebasement.com/github-pages-vs-netlify-free-hosting/

Практичные варианты превью для `mockup-v2`, по возрастанию усилий:

1. Локально: `python3 -m http.server` в папке клона, показать общине через screen-share/запись.
2. Второй публичный репозиторий-превью (например, отдельный repo только под макет) со своим github.io-адресом и `noindex` — живой сайт не затрагивается вообще.
3. GitHub Actions workflow, публикующий `mockup-v2` в подпапку/артефакт, если захочется автоматики.

## Рекомендация именно для этого проекта

**Основной путь: A.** `git clone -b gh-pages` → ветка `mockup-v2` → Claude Code редизайнит на месте по guardrails, референсы уровня Awwwards подмешиваются через путь C1 (скриншот → черновой фрагмент → переписка в реальный код страницы). Причины: сайт маленький (4 смысловые страницы), статичный, трёхъязычный кодом, а не страницами, и уже живёт на бесплатном GitHub Pages. Только путь A сохраняет всё это бесплатно и без миграции.

**Запасной путь: B2 (AIDesigner) + B5/C2 при необходимости.** Если редизайн «на месте» зайдёт в тупик по вкусу (агент будет давать однотипные варианты главной), сделать в AIDesigner 2–3 альтернативных hero/главных на бесплатных кредитах, экспортировать HTML и отдать Claude Code как референс в путь A. Если общине понадобится обсуждать макет «картинками» до кода, добавить звено UX Pilot → Figma → Figma MCP.

**Не использовать как основу:** Repaint (уводит хостинг и не отдаёт код), Capacity (ненужный React), Hostinger (lock-in + спорный экспорт), чистый wget (теряет i18n).

## Пошаговый пайплайн: от клона до превью макета

1. **Заморозка.** Зафиксировать текущий `gh-pages` коммитом-тегом `pre-redesign-snapshot`. Снять базовые скриншоты всех 4 страниц (1440 + 375) и список URL в `URL_BASELINE.txt`.
2. **Клон и ветка.** `git clone -b gh-pages …` → `git checkout -b mockup-v2`. Никакой работы в самой `gh-pages`.
3. **Инвентаризация.** Claude Code составляет `CONTENT_INVENTORY.md`: страницы, секции, тексты по трём языкам из `i18n-dict.js`, фото, внешние ссылки, формы, аналитика. Сверка с отзывами общины (центрирование, высота шапки, обрезанный логотип, кривое hero-фото) как первые пункты бэклога.
4. **Guardrails.** Записать в `CLAUDE.md` список «не трогать» из раздела A3 и правило: каждая новая строка интерфейса сразу в UK/EN/RO.
5. **Редизайн срезами.** Hero главной (с Higgsfield-видео или его poster-заглушкой) → остальные секции главной → `courses` → `food` → `donation`. После каждого среза: скриншоты, visual diff, коммит.
6. **Проверки перед превью.** Diff списка URL против `URL_BASELINE.txt` (пустой), grep по ключам i18n (ни один не потерян), клик-тест форм и всех внешних ссылок, проверка аналитики в исходнике, Lighthouse, открытие всех страниц в трёх языках.
7. **Превью.** Опубликовать по варианту 2 из раздела «Превью»: отдельный репозиторий, `noindex`, без основного домена. Ссылку — Анади и общине на ревью.
8. **Решение и перенос.** По итогам ревью: либо `mockup-v2` мёрджится в `gh-pages` (с повторной проверкой шага 6), либо остаётся жить как второй макет. Откат в любой момент: тег из шага 1.
